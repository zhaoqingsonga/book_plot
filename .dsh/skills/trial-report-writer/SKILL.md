## 零、机器生成器（优先调用，别手写）

报告已可由生成器自动装配，**优先用 `build_trial_report.R`，不要手写**：

```bash
cd /Users/m4/GitHub/book_plot
Rscript scripts/build_trial_report.R --list                    # 查可用试验
Rscript scripts/build_trial_report.R --trial <试验编号> --rank 100   # 生成到分析输出/

Rscript scripts/build_trial_report.R --trial <试验编号> --rank 100 --to-vault --force  # 发布到 vault（铁律 7 落点）
```

**分工**：
- **算数 + 判定 + 装配**全走代码：`report_rules.R` → `report_preflight.R` → `report_assemble.R`。
  §六-A 机器判定、图表分诊、表图编号、注、摘要段、`## 关联` 段、盖章行、frontmatter 都自动出。
- **叙述是唯一人工输入**：`分析输出/<试验ID>_yield_test/报告/叙述.md`，按 `## <名称>` 段落填，
  生成器只读不覆盖；不知道的留空（报告保留 `<<名称>>` 留白）。
- **试验配置**：`报告配置/trials/<试验编号>.yaml`（trial_no / experiment_id / 体裁 / 地点 / year /
  design / field_notes_md / sop_source）。

**仍需手写**的只剩：田间管理措施、试验地选择、群体观察要点、照片、育种判断句——
这些现场细节只有作者知道，生成器不编造。填进 `叙述.md` 即可，其余全自动。

`--preflight-only` 只出事实卡；`--skeleton-only` 出骨架；`--vault-root <dir>` 改发布目录（默认
`~/GitHub/Obsidian/02wiki/02-项目/2026年试验报告`）。

## 一、铁律（违反即作废）

1. **产量数字一律来自 book_plot 分析管线，禁止手算。**
   亩产、增产率、位次、晋级名单、优良组合/亲本统计——**必须**是 `run_analysis()` 的输出。
   **不许手写 SQL 算亩产，不许用 Python/R 重算，不许从图上读数。**
   原因：对照离群剔除（1.5×IQR）、两套增产基准、位次阈值、倒伏排除这四件事
   只在管线里有统一实现，手算出来跟报告、应用界面、导出表**全都对不上**。

2. **只读。** 不写 `data/` 目录、不写数据库、不改项目代码。
   唯一允许执行的脚本是 `scripts/analyze_trial.R`（只读库、只写 `--out` 目录）。

3. **管线出的图不一定能用。** 每张图都要过一遍分诊（见 §五）。
   渲染成空白的图**不得**放进正文；被剔除的图要在报告里写明**为什么不能用**。

4. **没有的照片写「待补」，不许拿别的试验的照片充数。**
   照片来源限本试验田间照片；产量前几名的材料没有照片就是没有，写待补。

5. **口径必须标出来。** "材料层 / 小区层"、"较临近对照 / 较平均对照"、
   "含对照 / 不含对照"——凡是百分比、均值、位次，表注或图注里必须交代清楚。
   同一份报告里两个口径混着写 = 读者会被误导 = 报告作废。

6. **人工田间评价与管线数字分层。** 田间评价负责"有没有问题"，
   管线负责"产量多少、排第几"。人工观察进附录，**不许拿人工结论改管线数字**，
   反过来也不许把管线数字写成田间观察。

   **人工评价的取数走报告附录 A.4「材料田间评价表」**（N-4.2 的样例：
   `~/GitHub/Obsidian/02wiki/02-项目/2026年试验报告/N-4.2-常规-初级产比-宿州-2026年试验报告.md` §A.4）。
   **不要自己再去翻 md 巡田笔记拼一遍**。那张表已经把三类来源合并到一行：
   巡田时间线四轮（`08-08｜` `09-01｜` `09-24｜` `10月｜`）+ 数据库田间备注
   （`库-备注｜` `库-08-30｜` `库-09-17｜`）+ 数据库各期评价
   （`库-苗期｜` `库-花期｜` `库-成熟期｜`），每格自带来源标签。

   **这张表要写进报告正文（附录 A），不是另开一页。** N-4.2 的教训：
   单独建页 = 报告里看不到，等于没交付。

   表里的**亩产与两套位次同样取自管线 CSV**（`数据表/yield_ranking.csv`），
   **不许手算**；位次是材料层口径，两套基准都要给。全表按亩产从高到低排。

7. **报告放 vault，不放仓库。** 输出到
   `~/GitHub/Obsidian/02wiki/02-项目/<年份>年试验报告/`，
   遵循 vault 的写作规范（frontmatter / wikilink / 图片嵌入）。

### Step 2 · 取试验设计参数

从 SOP 页抄 §一～§六 的内容（目的、方法、材料、设计、性状调查、田间管理）。
田间管理措施若 SOP 里没有，去 vault `02-项目/<年份>年田间调查/` 找；找不到就写
通用做法并在附录里标"待确认"，**不要编具体的施肥量/日期**。

### Step 3 · 算口径（从管线产物推，不重算产量）

详见 `references/口径与图表分诊.md`。要点：

- **材料层**：380 份材料，不含对照 → 报告里讲"材料表现"用这个口径
- **小区层**：400 个小区（含 20 个对照）→ 讲"试验规模"用这个口径
- **对照基准**：20 个对照按 **1.5×IQR** 剔离群 → 剩 19 个有效对照
- **增产两套基准**：`较临近对照`（最近邻对照小区）和 `较平均对照`（有效对照均值），
  **两个都要报**，并说清是哪个

### Step 4 · 图表分诊（不可省）

逐张打开 `图表/*.png` 看有没有实际内容，**空白图必须剔除并在报告里写明原因**。
判定规则与已知缺陷见 `references/口径与图表分诊.md`。

**已知缺陷（实测）**：
- 产量等级分布 / 增产分布：`case_when(..., TRUE ~ "兜底档")` 把 NA 行吞进最后一档，
  所以**图上的分母是全部 400 个小区**，不是有效数。图注必须交代这一点，并补一个
  剔除空值后的干净口径数字。
- 性状相关性矩阵 / 株高vs产量 / 百粒重vs产量：**当株高、百粒重整列为空
  （室内考种未开展）时，渲染出来是空白 PNG**——图生成成功了，但没信息量。
  这种图要剔除 + 在报告里写"管线已生成但本报告不予采用"及原因。
- 筛选前后性状对比：管线会**自动省略**全 NA 的指标面板（正常行为），图注说明只有几个面板即可。

### Step 5 · 找照片

```bash
ls ~/GitHub/Obsidian/02wiki/06-附件/ | grep -i "<试验编号关键词>"
```

- 照片放在 `06-附件/`，嵌入用**相对路径 markdown 语法** `![alt](../../06-附件/xxx.jpg)`

- 田间观察照片（对比位、亲本候选）属于**附录**，不是正文图

> ⚠️ **图片嵌入语法：本 vault 一律用 markdown 相对路径 `![alt](<路径>)`，
> 不要用 Obsidian wikilink `![[...]]`。**

> 见 `references/Obsidian-写作规范.md` §四。

## 六、口径陷阱（写之前必须知道）

口径陷阱分两类，本节分开列：

- **§六-A 机器判定**：判据全部来自管线已有数据，确定性可复算 ⇒ **已写成代码**，
  生成器会自动判定，并把结论句与「注：」写进报告对应位置。这些**不用手写**。
- **§六-B 人工判断**：机器判不了，得人拿主意或人写措辞 ⇒ 散文保留在此。

### 六-A、机器判定的口径规则

| | |
|---|---|
| 规则全表（名称 / 级别 / 判定式 / 结论句 / 注模板 / 文档锚点） | `references/口径规则表.md`（**自动生成，请勿手改**） |
| 规则源（唯一真相源） | `shared/analysis/report_rules.R` |
| 判定引擎 | `shared/analysis/report_preflight.R` → `report_preflight()` |
| 图表分诊 | 同上 → `rpt_triage_plots()`（**不读 PNG**，判据全来自管线数据） |
| 漂移防线 | `Rscript scripts/export_report_rules_md.R --check` |

规则条数与内容以 `references/口径规则表.md` 为准 —— **本节不复述规则表**，
复述就会两边漂移（skill 已经吃过一次亏：口径住文档、算数住代码，一批
`docs(skill): 补坑` 全是漂移的代价）。

跑 `report_preflight()` 时逐条判定，按级别落位：

| 级别 | 触发后果 |
|---|---|
| **阻断 blocker** | 核心口径不成立 ⇒ `ok=FALSE`，生成器不产出交付件、退出码 1 |
| **警告 warn** | 口径有瑕疵但可交付 ⇒ 正文/附录自动插披露句 |
| **提示 info** | 读者需要知道的细节 ⇒ 自动写进表图下的「注：」 |

**§六-B 里带 〔机器判定：…〕 标记的条目，生成器会自动处理。**
手写报告（生成器尚未覆盖的体裁）仍要按六-B 逐条查。

### 六-B、人工判断的口径陷阱

1. **同名碰撞**：多个对照小区都叫「中黄301」，按名称 join 会炸。
   必须用 `(名称, 亩产)` 或 `阶段名称` 做键。
2. **材料层 vs 含对照**：生育期分箱、相关性 r、均值——同一份报告里
   材料层和含对照层要**分别标注**，不能混。
   实测同一试验 `corr(生育期, 亩产)`：材料层 r=0.25 (n=373)，含对照 r=0.28 (n=392)。
3. **严格增产 vs ≥0%**：图里"增产"档按 ≥0% 归集，表里若按 >0% 算，
   差值就是持平的那几个（实测差 1 个）。图注里写清楚。
4. **生育期分箱必须材料层算**：含对照进去，均值会被拉偏（实测 95 天档：
   含对照 208.4 vs 材料层 204.5）。
5. **晋级率两个分母**：材料口径 90/380 = 23.7%，小区口径 90/400 = 22.5%
   （N-4.2 阈值 100 口径；阈值 60 时为 44 份 / 11.6% / 11.0%）。
   两个都对，但要说是哪个。
6. **淘汰数相加要闭合**〔机器判定：screening_not_closed / elimination_reasons_overlap〕：晋级 + 分离选单株 + 淘汰 = 总数。淘汰原因
   （位次不达标 / 分离 / 倒伏 / 无位次可判）计数**可重叠**，别指望三项之和
   等于淘汰数——N-4.2 阈值 100 实测淘汰 310 个小区（含 20 个对照位，
   材料层面 290 份），分类计数为 位次不达标 283 ｜ 倒伏排除 6 ｜ 无位次可判 26
   （20 对照位 + 6 缺产材料），5 份同时命中「位次不达标 + 重倒」，
   故三类之和比淘汰数多 5。

7. **同一份报告里可能有两套「晋级」口径**〔机器判定：parent_threshold_mismatch〕：`analyze_parent_cross()` 把亲本分析
   的晋级**写死为「较平均对照位次 ≤ 60」**，不跟 `--rank` 走。改阈值后
   表 4-5（筛选口径）与表 4-7/4-8（亲本口径）份数会不一致，
   **要在 §7.5 加 ⚠️ 说明、并在附录「待确认事项」记一条**，不许混着写。

8. **「分离」也有两套口径**〔机器判定：separation_in_promoted / trait_field_sparse〕：管线的分离通道按 `grepl("分离", 阶段名称)` 分流，
   而「阶段名称」经列名映射后是**材料编号**，**不看性状**；真正的性状分离记在
   质量性状列的 `99-分离` 取值里，**不参与晋级判定**。晋级材料表末列要加
   「性状分离」列逐份列明；且注意「无记录 ≠ 不分离」（`荚熟色` 等字段
   覆盖率极低），统计比例不能拿总小区数当分母。

   ⚠️ **判据是两个，不是只一个**：`99-分离` 是性状栏的**专用编码**，但
   **田间备注里人工写的「有分离 / 不纯 / 需提纯」同样算分离**。
   `analyze_screening()` 已内置 `detect_trait_segregation()` 合并这两个判据，
   晋级 / 分离选单株 / 淘汰三张表末列直接给「性状分离」列（备注来源标注为
   「备注：性状·关键字」）。**不要自己只扫 5 个性状栏**——会漏掉备注里的
   人工评语（N-4.2 漏 N26E085）。

   ⚠️ **转基因试验里判据 ② 语义不同**：备注写的「分离」在常规产比是「品系不纯、
   需提纯」，在转基因产比抓到的是 **V3 世代转基因抗性（抗草甘膦）分离**
   ——属预期观察，**≠ 品系不纯、不需提纯**（G-4.2 实测 28 条备注命中全是抗性分离）。
   转基因报告要把「形态性状分离（需提纯）」与「转基因抗性分离（鉴定记录）」
   **拆成两张表**，并把是否计入需提纯写进待确认事项。

9. **默认晋级位次阈值 = 参试材料数的前 25%**〔机器判定：threshold_neq_promoted_count / single_replicate〕：`analyze_screening()` 不传
   `rank_threshold_select` 时自动算 `ceiling(0.25 × 参试材料数)`（**对照小区不计入**，
   见 `count_materials()`）。N-4.2：380 份参试材料 → 阈值 **95** → 晋级 **76** 份。
   ⚠️ **阈值 ≠ 晋级份数**：AND 逻辑 + 并列 + 倒伏排除三重折损，实际入选只有
   阈值的 0.67~0.90 倍（95 → 76 份 = 0.80 倍）。CLI 用 `--rank` 覆盖默认值；
   App 滑块初值同源，上限随试验规模自适应。
   ⚠️ **`count_materials()` 数的是「行」不是「份」**：两重复试验行数 = 份数 × 2，
   管线默认阈值会大一倍（G-5.3：64 行 ↔ 32 份 ⇒ 管线默认 16，用户口径 8）。
   报告口径按**去重 stageid 份数**算，管线默认按行数算，两者要在正文写明差异
   并给多档实跑敏感性表。

10. **材料数 < 60 时亲本口径整个退化**〔机器判定：parent_rank_degenerate〕：`analyze_parent_cross()` 把亲本晋级写死为
    「较平均对照位次 ≤ 60」。位次数到不了 60 的小试验里，**所有**材料的亲本晋级率
    都 = 1.000，零区分度（实测 G-5.2 最大位次 42、G-5.3 最大位次 32）。
    写之前查 `max(较平均对照位次)`，≤ 60 就要在 §亲本 加 ⚠️、把「亲本晋级表现」
    图剔除并写明原因。

11. **方案里的「参考对照」在库里是 `is_ck=0`**：会被当普通材料一起筛选、一起算
    增产率、一起占「参试材料数」的分母（G-5.2 的 4 份参考对照，其中 G26M052
    中豆57 还晋级了）。正文要写明这个事实，并另给「剔除参考对照后」的份数对照。
    要不要改 `is_ck` 属**写库**，必须让作者本人决定。

12. **缺产材料 ≠ 离群对照置空**〔机器判定：missing_yield_materials / outlier_control〕：前者在库里就没产量（田间未测产），
    后者库里有产量但被 1.5×IQR 规则置空。图上都是「无产量」，成因不同，
    不要笼统写成「缺产」。

13. **多重复时对照基准按 `(place, rp)` 分组各算各的**：
    `compute_derived_yield_columns()` 先按 `(place, rp)` 分组，
    所以两个重复的「较临近对照增产率」**不可横向比**（G-5.3 宿州 rp1 对照均值
    158.13 vs rp2 110.89，差 30%，而材料均值几乎相同）。正文按重复分列。
    ⚠️ 别假设「多点 = 多重复」：G-5.2 多点测试是**单重复**，G-5.3 联合鉴定才是两重复。
    写之前先查 `GROUP BY place, rp`。

14. **⚠️⚠️ 试验里没有对照小区 ⇒ 晋级通道整条不成立**〔机器判定：no_control〕：
    管线**不生成** `promoted.csv`；全部行进 `eliminated.csv`、淘汰原因一律「未知」；
    增产率/位次全 NA；`increase_stats.csv` 里出现 `NA` / `-Inf` / `Inf`（**管线脏值，
    绝对不能进报告正文**）；依赖对照的 5 张图（亩产分布 / 产量等级分布 / 增产分布 /
    生育期分布 / 雷达图）**不生成**。
    ⇒ §晋级 写成「不适用 + 原因」，不是省略；只做产量描述。
    实测：`N-9.9-河北农科院-产比`（156 小区）、`N-9.9-邱老师品系展示`（12 小区）。

15. **⚠️ 查对照数别写 `is_ck = 1`**：`is_ck` 列存的是字符串 `'1.0'` / `'0.0'`，
    `where is_ck = 1` 查出 0 行，会误判成「这个试验没有对照」。
    正确写法：`where cast(is_ck as real) = 1`。

16. **⚠️「晋级」只看相对位次、不看绝对产量**：
    对照比材料群强很多时，会出现「增产品种 0 份、但仍晋级 N 份」。
    实测 `N-9.9-GY测试` 宿州（对照 250.13 vs 材料 196–208 kg/亩，增产 0 份，晋级 3 份）
    和 `N-9.9-常规-商业育种-宿州`（增产品种比例 10.13%，仍晋级 122 份）。
    ⇒ 摘要/结论必须同时写「晋级 N 份」和「增产品种 N 份」，否则读者会误解。
