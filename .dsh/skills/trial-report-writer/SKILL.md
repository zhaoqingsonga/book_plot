# trial-report-writer（试验报告撰写）

**已完成的样板（照着它写，不要另起炉灶）**：
`~/GitHub/Obsidian/02wiki/02-项目/2026年试验报告/N-4.2-常规-初级产比-宿州-2026年试验报告.md`

**分工**：`book-plot-field-book` 管"库里有什么"（查表、查字段），
`trial-plan-generator` 管"试验方案怎么生成"，**本 skill 管"报告怎么写"**。

---

## 一、铁律（违反即作废）

1. **产量数字一律来自 book_plot 分析管线，禁止手算。**
   亩产、增产率、位次、晋级名单、优良组合/亲本统计——**必须**是 `run_analysis()` 的输出。
   **不许手写 SQL 算亩产，不许用 Python/R 重算，不许从图上读数。**
   原因：对照离群剔除（1.5×IQR）、两套增产基准、位次阈值、倒伏排除这四件事
   只在管线里有统一实现，手算出来跟报告、应用界面、导出表**全都对不上**。

2. **只读。** 不写 `data/` 目录、不写数据库、不改项目代码。
   唯一允许执行的脚本是 `scripts/analyze_trial.R`（只读库、只写 `--out` 目录）。

3. **管线出的图不一定能用。** 每张图都要过一遍分诊（见 §五）。
   渲染成空白的图**不得**放进正文；被剔除的图要在报告里写明**为什么不能用**。

4. **没有的照片写「待补」，不许拿别的试验的照片充数。**
   照片来源限本试验田间照片；产量前几名的材料没有照片就是没有，写待补。

5. **口径必须标出来。** "材料层 / 小区层"、"较临近对照 / 较平均对照"、
   "含对照 / 不含对照"——凡是百分比、均值、位次，表注或图注里必须交代清楚。
   同一份报告里两个口径混着写 = 读者会被误导 = 报告作废。

6. **人工田间评价与管线数字分层。** 田间评价负责"有没有问题"，
   管线负责"产量多少、排第几"。人工观察进附录，**不许拿人工结论改管线数字**，
   反过来也不许把管线数字写成田间观察。

   **人工评价的取数走报告附录 A.4「材料田间评价表」**（N-4.2 的样例：
   `~/GitHub/Obsidian/02wiki/02-项目/2026年试验报告/N-4.2-常规-初级产比-宿州-2026年试验报告.md` §A.4）。
   **不要自己再去翻 md 巡田笔记拼一遍**。那张表已经把三类来源合并到一行：
   巡田时间线四轮（`08-08｜` `09-01｜` `09-24｜` `10月｜`）+ 数据库田间备注
   （`库-备注｜` `库-08-30｜` `库-09-17｜`）+ 数据库各期评价
   （`库-苗期｜` `库-花期｜` `库-成熟期｜`），每格自带来源标签。

   **这张表要写进报告正文（附录 A），不是另开一页。** N-4.2 的教训：
   单独建页 = 报告里看不到，等于没交付。

   表里的**亩产与两套位次同样取自管线 CSV**（`数据表/yield_ranking.csv`），
   **不许手算**；位次是材料层口径，两套基准都要给。全表按亩产从高到低排。

7. **报告放 vault，不放仓库。** 输出到
   `~/GitHub/Obsidian/02wiki/02-项目/<年份>年试验报告/`，
   遵循 vault 的写作规范（frontmatter / wikilink / 图片嵌入）。

## 三、执行流程（按顺序做，不要跳）

### Step 0 · 查试验 ID

```bash
cd /Users/m4/GitHub/book_plot
Rscript scripts/analyze_trial.R --list
```

### Step 1 · 跑管线，出全套产物

```bash
# 完整产物：图表 + 数据表 + Markdown/HTML/Excel
Rscript scripts/analyze_trial.R --exp <试验ID> --out "分析输出/<试验编号>"

# 结构化结论（≈190KB，务必落文件再 grep，不要整份塞上下文）
Rscript scripts/analyze_trial.R --exp <试验ID> --json --json-out /tmp/<试验编号>.json
```

产物布局：

```
分析输出/<试验编号>/
├── 图表/      16 张（产量等级分布、增产分布、亩产分布、生育期分布、
│              生育期vs产量、筛选前后性状对比、亲本晋级表现、雷达图、
│              性状分布×5、性状相关性矩阵、株高vs产量、百粒重vs产量）
└── 数据表/    yield_ranking / promoted / eliminated / cross_stats /
               parent_stats / overview / yield_stats / growth_stats / increase_stats
```

**数据表是写报告的主要数据源，图表是配图。**

### Step 2 · 取试验设计参数

从 SOP 页抄 §一～§六 的内容（目的、方法、材料、设计、性状调查、田间管理）。
田间管理措施若 SOP 里没有，去 vault `02-项目/<年份>年田间调查/` 找；找不到就写
通用做法并在附录里标"待确认"，**不要编具体的施肥量/日期**。

### Step 3 · 算口径（从管线产物推，不重算产量）

详见 `references/口径与图表分诊.md`。要点：

- **材料层**：380 份材料，不含对照 → 报告里讲"材料表现"用这个口径
- **小区层**：400 个小区（含 20 个对照）→ 讲"试验规模"用这个口径
- **对照基准**：20 个对照按 **1.5×IQR** 剔离群 → 剩 19 个有效对照
- **增产两套基准**：`较临近对照`（最近邻对照小区）和 `较平均对照`（有效对照均值），
  **两个都要报**，并说清是哪个

### Step 4 · 图表分诊（不可省）

逐张打开 `图表/*.png` 看有没有实际内容，**空白图必须剔除并在报告里写明原因**。
判定规则与已知缺陷见 `references/口径与图表分诊.md`。

**已知缺陷（实测）**：
- 产量等级分布 / 增产分布：`case_when(..., TRUE ~ "兜底档")` 把 NA 行吞进最后一档，
  所以**图上的分母是全部 400 个小区**，不是有效数。图注必须交代这一点，并补一个
  剔除空值后的干净口径数字。
- 性状相关性矩阵 / 株高vs产量 / 百粒重vs产量：**当株高、百粒重整列为空
  （室内考种未开展）时，渲染出来是空白 PNG**——图生成成功了，但没信息量。
  这种图要剔除 + 在报告里写"管线已生成但本报告不予采用"及原因。
- 筛选前后性状对比：管线会**自动省略**全 NA 的指标面板（正常行为），图注说明只有几个面板即可。

### Step 5 · 找照片

```bash
ls ~/GitHub/Obsidian/02wiki/06-附件/ | grep -i "<试验编号关键词>"
```

- 照片放在 `06-附件/`，嵌入用相对路径 `![[../../06-附件/xxx.jpg]]`
  （报告页在 `02wiki/02-项目/<子目录>/`，所以是上跳两级）
- 产量前几名的材料往往**没有**照片 → 表里写「待补」
- 田间观察照片（对比位、亲本候选）属于**附录**，不是正文图

### Step 6 · 成文

骨架见 `references/2025-报告骨架.md`。**逐节照填，不要自创体裁。**

### Step 7 · 自检（交付前逐条打勾）

见 §七。

**每个表下面必须有「注：」**，写清口径、单位、限制。

## 六、口径陷阱（写之前必须知道）

1. **同名碰撞**：多个对照小区都叫「中黄301」，按名称 join 会炸。
   必须用 `(名称, 亩产)` 或 `阶段名称` 做键。
2. **材料层 vs 含对照**：生育期分箱、相关性 r、均值——同一份报告里
   材料层和含对照层要**分别标注**，不能混。
   实测同一试验 `corr(生育期, 亩产)`：材料层 r=0.25 (n=373)，含对照 r=0.28 (n=392)。
3. **严格增产 vs ≥0%**：图里"增产"档按 ≥0% 归集，表里若按 >0% 算，
   差值就是持平的那几个（实测差 1 个）。图注里写清楚。
4. **生育期分箱必须材料层算**：含对照进去，均值会被拉偏（实测 95 天档：
   含对照 208.4 vs 材料层 204.5）。
5. **晋级率两个分母**：材料口径 44/380 = 11.6%，小区口径 44/400 = 11.0%。
   两个都对，但要说是哪个。
6. **淘汰数相加要闭合**：晋级 + 分离选单株 + 淘汰 = 总数；淘汰原因
   （位次不达标 / 分离 / 倒伏）也要能加回淘汰总数。
