## 一、四组必须分清的口径

### 1. 材料层 vs 小区层

| | N-4.2 实测 |
|---|---|
| 小区总数 | 400 = 材料 380 + 对照 20 |
| 有产量小区 | 392 = 材料 373 + 对照 19 |
| 材料均值亩产 | **188.19 kg**（373 份，sd 42.35，CV 22.50%） |
| 全部有产量小区均值 | 190.46 kg（392 个，sd 42.76，CV 22.45%） |

**报告里讲"参试材料表现"→ 材料层；讲"试验规模/总盘子"→ 小区层。**
混着写读者会以为 190.46 是材料均值。

### 2. 对照基准：1.5×IQR 剔除离群

N-4.2 有 20 个对照小区，其中 **N26E380 小区产量 2 kg（≈138.9 kg/亩）**，
管线按 1.5×IQR 判为离群并置空 → **19 个有效对照**。

| | 数值 |
|---|---|
| 有效对照均值 | **235.13 kg/亩** |
| 范围 | 201.49–279.31 kg/亩 |
| sd / CV | 20.94 / 8.91% |
| 若把离群算进去（20 个） | 230.31 kg/亩 |

离群对照**必须**在报告里点名（N26E380），并进附录「待确认事项」——
人工要复核是地力异常还是操作失误。

### 3. 两套增产基准

| | 含义 | N-4.2 |
|---|---|---|
| **较临近对照** | 该小区**最近的那个对照小区**作基准 | 41 份增产（>0%） |
| **较平均对照** | 全部**有效对照的均值**作基准 | 49 份增产（>0%） |

对应的位次列同理（`较临近对照位次` / `较平均对照位次`）。

**两个都要报**，并说清是哪个。管线筛选（`analyze_screening`）对两个位次列用
**AND 逻辑**：两个都 ≤ 阈值才算晋级。阈值默认 60。

### 4. 含对照 vs 不含对照（相关性、分箱）

同一份数据、两种算法：

| 指标 | 材料层 | 含对照 |
|---|---|---|
| `corr(生育期, 亩产)` | r = 0.25（n = 373） | r = 0.28（n = 392） |
| 生育期 95 天档平均亩产 | 204.5 kg | 208.4 kg |

**分箱必须材料层算**——对照的生育期是另一个水平（95.4 vs 材料 93.1 天），
混进去会把均值拉偏。

## 二、晋级筛选的数要闭合

```
400 小区 → 晋级 44 → 分离选单株 0 → 淘汰 356
淘汰的 356 个小区含 20 个对照位 → 材料层面实际淘汰 336 份
淘汰原因（计数可重叠）：位次不达标 329 ｜ 倒伏排除 6 ｜ 无位次可判 26
  ├ 26 = 20 个对照位（基准小区，无位次）+ 6 份缺产材料
  └ 5 份同时命中「位次不达标 + 重倒」→ 三类计数之和比淘汰数多 5
```

- 晋级率：材料口径 44/380 = **11.6%**；小区口径 44/400 = **11.0%**
- 淘汰原因**计数可重叠**（同一材料可能既位次不达标又重倒），但分类计数要能对上
- 默认排除倒伏等级：`9-严重倒`、`7-重倒`（N-4.2 实测触发 6 份，全是 `7-重倒`；
  其中 1 份 N26E390 同时缺产，淘汰原因只有「倒伏-重倒」）
- 分离选单株用**严格小于**阈值，晋级用 **≤** 阈值
- **对照位没有位次（NA）**，既不进晋级名单，也被计入淘汰名单（原因记「未知」）
- 位次是**材料层**口径且**并列取相同名次**（最小排名）：N-4.2 较临近最大位次 373、
  较平均最大位次 372（373 份有产量材料）。所以阈值边界上的并列材料会一并入选，
  **实际入选数可能多于阈值本身**——阈值 60 时单套口径分别是 60 份和 64 份，
  AND 逻辑下最终 44 份。

### 阈值杠杆（N-4.2 管线实跑，同一试验 YIELD_20260527153649_1915）

| 晋级位次阈值 | 晋级 | 平均亩产 | 亩产区间 | 最低亩产较对照均值 235.13 |
| ---: | ---: | ---: | --- | ---: |
| 20 | 15 | 266.57 | 251.93–284.86 | +16.80 |
| 30 | 20 | 261.11 | 241.79–284.86 | +6.66 |
| 40 | 29 | 254.95 | 236.23–284.86 | +1.10 |
| 50 | 34 | 252.30 | 234.14–284.86 | −0.99 |
| **60** | **44** | **248.82** | **229.28–284.86** | **−5.85** |
| 70 | 53 | 245.38 | 223.72–284.86 | −11.41 |
| 80 | 64 | 242.94 | 222.33–284.86 | −12.80 |
| 100 | 90 | 236.45 | 215.39–284.86 | −19.74 |

**阈值越大，晋级群体的产量下限越低。**
这些数是管线实跑出来的，**不许拿 `yield_ranking.csv` 的位次列自己推算晋级数**。

反查（目标晋级份数 → 所需阈值，实测档位）：
20 份→T=30、30 份→T=50、44 份→T=60、50 份→T=70、64 份→T=80、90 份→T=100。
**阈值 ≠ 晋级份数**——AND 逻辑 + 并列入选 + 倒伏排除/分离分流三重折损，
实际晋级数只有阈值的 **0.67–0.90 倍**。

### 应用内调阈值的两个坑（源码实测）

`shared/mod_yield_test.R` 里 `screening_result()` 是 reactive，滑块一动就重跑
`analyze_screening()`，**「品种筛选」标签页**内实时更新：晋级材料表、
分离选单株表、淘汰材料表、筛选前后对比图、雷达图。

但有两处**不跟滑块走**：

- **「亲本分析」标签页**用的是 `rv$analysis_result` 快照（`parent_stats` /
  `cross_stats` / `parent_plot`）——改阈值不更新，所以表 4-7/4-8、图 4-12
  亲本晋级表现必须**重跑管线**才能改。
- **「导出」标签页**打包的是 `rv$analysis_result`（`build_analysis_zip()`），
  **不是当前滑块值**——拖到 70 再导出，拿到的仍是阈值 60 的表和图。
  报告正文要新阈值的结果，只能命令行重跑。

## 三、图表分诊（16 张）

管线 `--out` 会出 16 张图。**每一张都要用 Read 工具打开看过**，
不要凭文件名判断。

### ✅ 可直接用（13 张）

| 图 | 备注 |
|---|---|
| 亩产分布 | 均值/中位线由管线标注 |
| 生育期分布 | — |
| 生育期vs产量 | **图注里的 r 和 n 是什么口径要自己核对**，管线图注用含对照口径 |
| 性状分布_花色 / _叶形 / _茸毛色 / _结荚习性 / _倒伏性 | — |
| 筛选前后性状对比 | 管线**自动省略**全 NA 指标面板，面板少是正常的，图注说明即可 |
| 亲本晋级表现 | — |
| 雷达图 | 产量前 5 |

### ⚠️ 能用但必须加注（2 张）

**产量等级分布**、**增产分布**。

根因（`shared/analysis/analysis_yield_core.R`）：

```r
dplyr::case_when(
  亩产_kg >= 200 ~ "(≥200kg)",
  ...
  TRUE ~ "(<120kg)"      # ← NA 也落进这一档
)
```

`case_when` 的 `TRUE ~` 兜底档会把 NA 行一并吞进去，于是**图上的分母是全部
400 个小区**，而不是有效数。

处理办法（图注里写清楚，并补一个干净口径）：

- 产量等级分布：图上分母 400，其中 8 个无产量小区（7 份缺产材料 + 离群对照
  N26E380）落进 "<120kg" 档。剔除空值后的材料层分布：≥200 kg **159 份（42.6%）**、
  160–199 kg 125 份（33.5%）、120–159 kg 60 份（16.1%）、<120 kg 29 份（7.8%），分母 373。
- 增产分布：图上分母 400，其中 27 个无增产率小区（20 个对照小区本身不与对照比
  增产率 + 7 份缺产材料）落进"减产(< −10%)"档。图里"增产(0–9%)"按 **≥0%** 归集，
  含 1 个持平材料（N26E293，0.00%），所以图上"增产"合计 42；
  §表里严格增产（>0%）口径是 41 份。**两个数都要说，别让人以为对不上。**

### ❌ 不能用（3 张）——剔除并写明原因

**性状相关性矩阵**、**株高vs产量**、**百粒重vs产量**。

根因：株高、百粒重字段 **400/400 全为空**（室内考种未开展）。

- `plot_correlation_matrix()` → `cor(..., use="complete.obs")` 对整列 NA 返回 NA 矩阵
  → corrplot 画出**空白 PNG**
- `plot_trait_vs_yield()` → 无任何散点 → **空坐标系**（只剩色标和坐标轴）

⚠️ **"图生成成功了" ≠ "图有内容"**。这些 PNG 文件存在、有尺寸，但里面没有数据。
必须剔除，并在报告里写：

> 管线已生成但本报告不予采用的 N 张图：分析管线同时输出了「性状相关性矩阵」
> 「株高 vs 产量」「百粒重 vs 产量」，但**株高与百粒重字段 400/400 全部为空**
> ——相关性矩阵因参与计算的变量整列缺失而渲染为空白图，散点图因无任何散点而
> 只剩空坐标系。这三张图无有效信息量，故未纳入正文；室内考种数据入库后重跑
> 管线即可自动生成。

对比：`plot_selection_comparison()` 有 `not_all_na` 过滤，会**自动丢掉**全 NA 的指标
面板——这是正确行为，不需要额外处理。

## 三·五、多点测试专属坑（N-5.2 实测，2026-10-28）

### 1. 分地点图 vs 全局图：全局图在数据缺失时会说谎

多点试验管线同时出「全局图」和「分地点_XXX图」。**部分试点缺产量时**：

- 全局「增产分布」把无增产率的行全部塞进「减产(<−10%)」兜底档
  → N-5.2 实测全局图显示「减产 96.5%（1447/1500）」，**完全是假象**
- 全局「亩产分布」的均值线是**小区层口径（含对照）**，不是材料层
  → N-5.2 图上标 193.5，材料层实为 189.93，差 3.5 kg，图注必须交代

**处理**：多点报告正文一律用 `分地点_<地点>_*.png`；全局版若剔除，
须在正文写明剔除原因与图上的失真数字。

### 2. 无产量点的图「有像素无信息」

缺产量的点，`分地点_增产分布_XXX.png` **不是空白图**——像素占比可达 49%，
因为一根柱子顶满「减产」档。**像素法查不出来**，必须看图 + 看该点有效增产率数。
N-5.2 实测 9 个无产量点各出一张这种图，全部剔除。

### 3. 筛选数不闭合是正常的

无产量的点没有位次 → 既不晋级也不淘汰，`淘汰原因` 记「未知」。
N-5.2 实测每点 134 材料 = 102 淘汰 + 32 无位次可判。**不要当 bug**，
但要写清「134 = 48 晋级 + 102 淘汰 + 28 无位次」这种闭合式。

### 4. 对照品种可能与 SOP 不符

N-5.2：SOP §3.2 规定宿州、濉溪用**皖豆37**，实际入库为**中黄301**。
必须逐点从库里查实际对照品种并与 SOP 比对，不符的进「待确认事项」——
这直接影响增产率基准的解释。

### 5. 管线 `分析报告.md` 里有 `Inf`

分地点产量统计表对无产量点会输出 `最高亩产 = -Inf` / `最低亩产 = Inf`
（`max(numeric(0))` 的结果）。**不要抄进报告**，无产量点写「待回填」。

## 三·六、脚本化写报告的最小可复用件

手写 500 行 Markdown 容易抄错数字。三个脚本足够（见 `~/Desktop/试验报告/`）：

| 脚本 | 作用 |
|---|---|
| `extract_numbers.py` | 从管线 CSV 抽全部数字成 JSON，**只取数不算数** |
| `build_report.py` | 按骨架格式化输出 MD，数字全部来自 CSV 变量 |
| `check_report.py` | 对照 §七 清单机器自检（80 项） |

关键坑：**`yield_ranking.csv` 用中文列名（`亩产 (kg)`），
`promoted.csv` / `eliminated.csv` 用拼音列名（`MuChan`）**——
同一个取值函数要兼容两套，否则晋级材料统计会静默取到空值（`statistics.mean`
直接抛 `StatisticsError`）。

## 四、其它坑

1. **同名碰撞**：所有对照小区都叫「中黄301」（N-4.2 里有 20 个）。
   按名称 join 会把 20 行交叉乘起来。**必须用 `(名称, 亩产)` 或 `阶段名称` 做键。**

   - `yield_ranking.csv` 用中文列名（`品种名称`/`亩产 (kg)`/`较临近对照增产 (%)`…）
   - `promoted.csv` 用拼音列名（`stageid`/`MuChan`/`XiaoQuChanLiang`/`ShengYuQi`/
     `JiaoLinJinDuiZhaoZengChan`/`JiaoLinJinDuiZhaoWeiCi`/`JiaoPingJunDuiZhaoZengChan`/

   写表时人工翻成中文。
